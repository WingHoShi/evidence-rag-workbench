# Evidence RAG Workbench 产品规格

## 目标

构建一个面向个人资料管理的本地可信知识库 Web 应用。用户在指定知识库内上传文档、等待异步解析后提问；系统必须返回可追溯的原文依据，证据不足时必须拒答。

## 用户与边界

- 单用户、本地运行，不提供登录、跨设备同步、多人协作或公网服务。
- 用户可创建多个彼此隔离的知识库；提问时必须选择一个知识库，默认不跨库检索。
- 上传的原始文件复制到应用数据目录，绝不修改用户原文件；删除只影响副本、索引和应用本地历史。
- 支持 Markdown、TXT、DOCX、可复制文本 PDF；单文件上限 20MB，单知识库累计上限 100MB。
- 扫描件、图片、OCR、复杂表格和旧版 `.doc` 不在首版范围内，应给出中文提示。

## 技术决策

- 前端：React + TypeScript；后端：FastAPI。
- 元数据与历史：SQLite；向量：Qdrant；本地 Embedding：`multilingual-e5-small`。
- 检索：先建立纯向量基线，再使用 BM25 + RRF 融合；Reranker 仅在评测证明有必要时再加入。
- 生成：使用 `.env` 中的 OpenAI-compatible API Key；设置页面不保存 API Key，只保存非敏感模型与检索参数。
- 问答：严格基于检索证据，显示原文引用；无资料、无有效引用或证据不足时拒答。外部文档视为不可信内容，不能改变系统指令。
- 历史：持久化保存在本地；每条回答保存引用的文档版本和 Chunk。

## Demo 与评测

- 固定 Demo 使用约 30 至 50 篇 LangGraph 官方核心文档，保存来源 URL、抓取时间、内容哈希；只提交来源清单和采集脚本，不分发官方文档全文。
- 增加明确标记为受控评测数据的原创文档，覆盖新规则、冲突条件、更新公告和提示注入样本。
- 人工维护 40 条金标题，涵盖中英文提问、中文问英文文档、跨段问题和应拒答问题。
- 报告包含 Recall@5、引用命中、拒答正确性、平均检索耗时、平均生成耗时；不预设或虚构宣传指标。

## 交付与安全

- 开发期使用原生 Python/Node；核心功能稳定后再使用 Docker Desktop + Docker Compose 交付 FastAPI 与 Qdrant。
- API Key、上传资料、模型缓存、索引、日志和生成结果均不进入 Git。
- 项目先仅使用本地 Git；不创建远程仓库或推送代码。
